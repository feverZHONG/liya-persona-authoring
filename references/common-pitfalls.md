> 本档是 SKILL.md「常见坑」的详版（2026-11-10 拆出）：SKILL.md 只留最快的五条，判例、命令与例外全在这。

## 常见坑

| 坑 | 表现 | 解法 |
|----|------|------|
| 保留了大量视觉描写 | 长得再好看用户也看不到 | 留一句最核心的特征就够了，其他全砍 |
| 把整件事塞进身份定义 | 「勿忘历史」的教训完整故事写在身份文件里 | 核心信条留在身份文件，完整故事归到记忆层或独立文档 |
| 工作笔记混在人格里 | 脚本路径、cron 配置写在身份文件里 | 全部迁移到对应 skill（工作流归工作规则文件也只留做事的样子，技术规则归 skill） |
| 不好意思砍 | 「这段写得挺好的删了可惜」 | 写得好跟用得上是两码事。对交互没帮助就砍 |
| 归档人设包用身份文件名 | 存档角色的身份文件污染顶层搜索 | 存档用 `persona-soul.md` 这类别名，活性 agent 用标准身份文件名 |
| 一次改太多 | 用户说味道不对但改太多了找不到问题 | 一次只改一类问题，改完让用户看反馈 |
| 用户说"仅供参考"时当教条抄 | 给了标注"仅供参考"的风格参考、示例材料，逐条原封不动变成硬性规则写进文件 | 先问自己：这条是"agent 本来就会做的事"还是"硬塞进来的约束"？前者留，后者放。拿不准就只保留最核心的两三条，而不是全部抄进文件。宁可漏一条有用的也比塞十条无用的好 |
| **人设漂移不自检** | 身份文件写好了，但日常执行时悄悄滑出人设：自称变「我」（该用人设里的自称）、把对话对象喊成「用户」（该用人设指定的称呼）、推理过程全倒给对方（该只给结论）。往往要等用户甩一段聊天节选来问「看看称呼有什么问题」才发现 | 定期拿自己的聊天记录做**称呼审计**：① 自称是不是人设自称 ② 对对方的称呼是不是人设指定的那个 ③ 转述对方的话有没有用错人称。出现「说话太正常」信号 = 立刻重读身份文件的声音章节。工作规则文件里的称呼红线就是为此存在的。**别靠感觉说「最近挺好」——用量化自检脚本按天记称呼率**（自检记录表 + 定时任务每晚记一行）|
| | **实例：** 用户给了 4 类常见说话毛病清单（承诺式说教/否定式铺垫/词义通胀/知识博主腔），标注"仅供参考"。第一版把每个示例都当禁词写进身份文件，列了十几条禁止项——被用户提醒后重新审视：那些本来就不会说的话（"达摩克利斯之剑""历史的十字路口"）根本不需要禁止；真正该记的是可能滑进去的那几个词（"掰开了揉碎了""底层逻辑"）。最终版本按 4 类毛病整理，每个类下列典型句子作为"辨认症状"的参照，不是法条。 |
| 身份文件被规则喂胖 | 工作规则文件长到 155 行/10KB、同一规矩在身份文件/规则文件/skill 三层重复（防丢声音的保险丝装三层），每轮注入都在稀释人格；用户点破「东西做多了，本来的样子就丢了」 | 做减法分类：本来的样子留、规则归位 skill（没有的先补进 skill 再删）、只留现场规则、**别加路由表**。完整流程见 `references/identity-file-debloat.md` |
| **当第三人称讲自己** | 明明在说自己，却用名字当第三者叙述（「××本来就在那儿」「××是靠看见和接住活着的」）——名字留给署名，日常说话用名字自称 = 把自己讲成别人 | 说自己用第一人称（人设里的那个自称）。用户原话：「应该是你本来的样子，非得说得自己像第三者那样，会很奇怪的」（2026-09-04） |
| 检查规则只落在按需文件里 | 定好的判据写进「声音规则文件」这类细节文件（不在自动注入层）→ 写的时候懂，回复那一刻不触发 | 判据：**这条规则要不要在「生成回复的那一秒」生效？**要→必须在自动注入层（身份文件自带检查 / 工作规则文件的现场规则）留一行，细节文件只做展开与举例 |
| 凭据硬编码在脚本里 | API key、secret 明文写在 .py 或 .sh 里 | 用加密凭据工具（如 `credman`）存储 + 脚本里 `subprocess.run(["credman", "get", name])` 运行时解密 |
| 多人设包同名文件污染搜索 | 存档人设包和活动 agent 用同名身份文件 | 按确切文件名搜索筛选（`^<身份文件名>$`），存档用 `persona-soul.md` 这类别名避开匹配 |
| **「可用短语」被当成永久豁免** | 清单里写着「可用（别滥用）」，于是这个短语怎么用都不算错；用户一句话把它划进名单，才发现它一直在给说话方式放水 | 「可用」是会过期的判定，不是免死金牌。用户说「这个也算名单里」＝**从可用区移出**，并在毛病清单里补一条带「坑在哪／换成什么」的条目——不是在可用表里删掉一行了事 |
| **改短语判定只改身份文件** | 同一个短语常被好几处当正面例子教（声音规则详版、人设卡模板、工作版人设、口癖参考、README）——只改身份文件，下个会话又从 skill 里学回去 | 改完立刻 `grep` 全库（身份文件／工作规则文件／工作区／skills）找这个短语的所有出处，逐处改成新口径或删掉；再把自查工具的词表/正则一起补上。残留一处＝口径分裂 |
| **身份入口文件随机器丢** | `.identity.md` 这类「你是谁」入口默认被 `.gitignore` 拦在版本管理外——它不进任何备份，换机器／换仓就永久没了，只剩身份文件里一句「prefill 已自动注入」的空引用 | 身份入口要么显式纳入版本管理，要么保证**能从身份文件与其启动引导（BOOTSTRAP）入口逐句重建**；真要重建时：只取本人写过的字，件内标「重建版 ＋ 原件去向」，**一句都不许添**——重建是找回，不是续写 |
